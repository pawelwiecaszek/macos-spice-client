# Cubic cosmetic stroke contract

C1 stroke slice B, 2026-11-17. Curves use the existing brush, foreground ROP, clip union,
native surface formats and endpoint-exclusive cosmetic line rasterizer. Styled strokes
are still separate. The installed Phase 5 app and existing PR remain unchanged.

## Compatibility evidence

Pinned reference: [spice-common@58d375e5eadc6fb9e587e99fd81adcb95d01e8d6](https://gitlab.freedesktop.org/spice/spice-common/-/blob/58d375e5eadc6fb9e587e99fd81adcb95d01e8d6/common/canvas_base.c#L2773).
The [public protocol](https://www.spice-space.org/spice-protocol.html) identifies Bezier
segments but does not mandate flattening tolerance. Quantized reference subdivision is
compatibility evidence, not a new protocol requirement.

Each cubic starts at the previous **rounded integer** endpoint reconstructed in fixed
28.4 coordinates. Control triples retain their raw fixed-point values. Subdivision uses
signed midpoint averages truncated toward zero; its flatness test quantizes dot products
before comparing determinants. A simple floating-point distance test differs even for
small inputs. The native implementation uses an original iterative De Casteljau planner
and Int128 arithmetic so hostile coordinate products cannot overflow narrow integers.

repository. Inputs are raw fixed28.4; output points are rounded integer coordinates and

## Deliberate robustness differences

The reference fails to terminate on an all-identical zero-chord curve and flattens
collinear backtracking controls prematurely. The native planner terminates a control
hull confined to one rounding cell, subdivides backtracking projections, and handles
sub-quarter-pixel chords whose quantized norm becomes zero. These safeguards are tested;
universal bit identity with the reference's pathological behavior is not claimed.

A shared per-draw budget allows at most 65,536 node visits, 65,536 generated endpoints
and subdivision depth 32. The complete visible line plan is additionally capped at
65,536 entries and retains the existing 8 Mi visible-step/clip-test budget. All planning
finishes before any pixel is modified, so exhaustion cannot paint earlier straight or
curved segments partially.

Solid-only pruning uses a conservative control hull outside the visible bounding box
with a one-pixel rounding margin. A skipped piece still emits its actual rounded endpoint
so following segments start correctly. This shortcut must not be used to calculate a
future dash phase or curve length. Entirely empty plans avoid requesting mutable pixel
storage. No allocation occurs per rendered pixel.

## Validation boundary

Tests lock the five reference polylines and golden raster pixels; cover multiple cubics,
straight/cubic continuation, closed XOR figures, clipping versus a full render, native
16-bit colors, zero-chord and backtracking cases, extreme coordinates and shared-budget
exhaustion with unchanged pixels. A synthetic display message exercises mixed paths.
Existing solid-line, ROP3 and real-server image replays remain regression gates.

Independent review passed. Live curve-specific captures remain pending; an ordinary
launch alone does not prove the guest emitted a cubic stroke. Axis-aligned dashed figures have a separate verified slice; diagonal/curved styled
strokes and text rendering remain unfinished C1 work.
